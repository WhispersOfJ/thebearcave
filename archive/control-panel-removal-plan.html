4D. New __stack_api Design

# BEFORE: single gateway
function __stack_api
    curl ... "https://bearcave.$HOST_IP.nip.io$argv[2]"
end

# AFTER: direct service calls with env-var-driven config
function __stack_api
    # DEPRECATED — kept for backward compat during migration
    # New functions should call services directly
    set -l method $argv[1]
    set -l path $argv[2]
    # ... parse path to determine target service ...
    # ... call service API directly ...
end

# NEW: per-service helpers
function __arr_api
    set -l app $argv[1]    # radarr or sonarr
    set -l method $argv[2]  # GET/POST
    set -l path $argv[3]
    set -l url "http://$app:7878"  # or 8989 for sonarr
    set -l key (eval echo \$$app:toupper)_API_KEY
    curl -sS -X $method "$url$path" -H "X-Api-Key: $key"
end

function __plex_api
    set -l method $argv[1]
    set -l path $argv[2]
    curl -sS -X $method "http://host.docker.internal:32400$path" \
        -H "X-Plex-Token: $PLEX_TOKEN"
end

function __nzbdav_api
    set -l method $argv[1]
    set -l path $argv[2]
    curl -sS -X $method "http://nzbdav:3000$path" \
        -H "X-Api-Key: $FRONTEND_BACKEND_API_KEY"
end

7. Catalog System

Decision Required

The catalog lets you install/remove third-party tools (Uptime Kuma, Dozzle, Beszel, etc.) from the web UI. Options:

  1. Keep as fish function — stack-catalog install uptime-kuma → reads catalog/registry.json, runs docker run via helper socket
  2. Standalone script — scripts/catalog.sh install uptime-kuma (no fish dependency)
  3. Drop entirely — users run docker run manually (the catalog entries are just docker-compose snippets)

Recommendation: Option 1 (fish function) — keeps the curated catalog accessible from the terminal.

10. Rollback Strategy

Git-based rollback

Every phase is a separate commit. Rollback = git revert <commit>. The control panel Docker image is built from source, so reverting the compose change + rebuilding restores the service.

# Rollback Phase 4 (control panel removal):
git revert <phase-4-commit>
docker compose up -d control-panel --build
# Service restored in ~2 minutes

Branch-based rollback

Create a remove-control-panel branch. Merge to main only after all phases pass. If anything breaks, merge main back into the branch to restore.

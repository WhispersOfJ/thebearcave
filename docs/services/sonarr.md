# Sonarr

Sonarr manages the TV library in the eight-service stack.

| | |
|---|---|
| Image | `ghcr.io/hotio/sonarr:release-4.0.19.2979` |
| Port | 8989 |
| Network | `bearcave` |
| Config | `config/sonarr/` |
| Depends on | `nzbdav_rclone` healthy, with restart cascade |

## Paths

| Host path | Container path |
|---|---|
| `config/sonarr/` | `/config` |
| `media/shows/` | `/data/shows` |
| `/mnt/remote/nzbdav` | `/mnt/remote/nzbdav` with `rslave` propagation |

The TV root is `/data/shows`; this must match the existing Sonarr database.

## Download client

Configure InfiniDysk as a SABnzbd-compatible client:

- Host: `nzbdav`
- Port: `3000`
- API key: `FRONTEND_BACKEND_API_KEY`
- Root folder: `/data/shows`

Prowlarr supplies indexers. Unpackerr watches Sonarr’s queue and extracts completed
archives before import.

If imports fail, verify the FUSE mount first:

```bash
docker exec nzbdav_rclone mountpoint -q /mnt/remote/nzbdav
docker compose logs --tail=100 sonarr nzbdav unpackerr
```

## DB bloat maintenance

Sonarr's database hits the same MediaInfo-blob growth as Radarr (AGENTS.md
landmine #9): `scripts/check_radarr_db_size.py` with `--blob-table EpisodeFiles`
detects it, and `stack-sonarr-prune` (backed by `scripts/prune_sonarr_db.py`)
remediates it: it stops sonarr, backs up `sonarr.db` + `logs.db` to
`config/sonarr/Backups/manual-maintenance-<ts>/`, prunes `EpisodeFiles.MediaInfo`
and history older than 90 days, vacuums, verifies integrity, and resumes sonarr.
The 2026-09-02 maintenance-digest sweep found a 3.2 GiB sonarr.db with ~2.0 GiB
in `EpisodeFiles.MediaInfo` — the first live instance of this class on Sonarr.

```bash
stack-sonarr-prune -y              # prune now (stop/start handled)
stack-sonarr-prune --dry-run       # report what would be done, touch nothing
```

The checker's blob table is parameterized so Radarr (`MovieFiles`, the
default) and Sonarr (`EpisodeFiles`) share one gate — detection and
remediation cannot drift apart. MediaInfo is regenerated by a library
rescan/analyze after pruning, so no library data is lost.
